# DONBEOLJA Trading Page Specs

## 목적
이 문서는 `홈`, `거래기록`, `전략상태` 화면을 실제 구현 직전 수준까지 구체화한 명세다.

원칙:
- 구현은 아직 시작하지 않는다.
- 현재 문서는 와이어보다 한 단계 더 구체적인 `컴포넌트/데이터/상태/우선순위`를 고정한다.
- 시각 톤은 `밝은 뉴트럴 기반 + 선명한 거래 정보 대비`를 따른다.

---

## 1. 홈 상세 명세

### 페이지 목적
사용자가 첫 진입 후 5초 안에 아래 네 가지를 파악해야 한다.
1. 현재 돈이 얼마인가
2. 오늘과 최근 손익이 어떤가
3. 최근 신호/체결이 있었나
4. 전략은 정상인가

### 화면 구조

#### A. Hero KPI 줄
카드 5개 고정
1. `현재 총자산`
2. `가용 자금`
3. `사용 중 자금`
4. `오늘 손익`
5. `최근 7일 손익`

카드 규칙:
- 숫자는 가장 크게
- 보조 설명은 1줄 이하
- USDT 기준이면 `≈ KRW` 보조 표기 허용
- 상승은 그린, 하락은 레드, 중립은 슬레이트

#### B. 왼쪽 메인 블록: `자금과 손익`
보여줄 항목:
- 총자산
- 가용 자금
- 사용 중 자금
- 총 손익
- 오늘/7일/30일/6개월 손익

행동 버튼:
- `수익 보기`
- `입출금 보기`

#### C. 오른쪽 메인 블록: `최근 신호 / 최근 체결`
상단 탭 또는 2단 리스트 허용

최근 신호 목록 컬럼:
- 시각
- 마켓
- 방향
- 등급
- 상태

최근 체결 목록 컬럼:
- 시각
- 마켓
- 방향
- 체결가
- 손익

행동 버튼:
- `거래기록 보기`

#### D. 하단 왼쪽 블록: `쉬운 수익 카테고리`
고정 항목:
- 오늘 손익
- 최근 7일 손익
- 최근 30일 손익
- 최근 6개월 손익
- 총 손익

규칙:
- 각 항목은 숫자만 빠르게 읽히게
- 차트보다 우선
- 사용자가 가장 익숙한 수익 요약 카드처럼 보여야 함

#### E. 하단 오른쪽 블록: `전략 상태 요약`
항목:
- 서버 우선 전환 진행률
- 현재 신호 원천
- 정본 신호 상태
- 현재 막는 이유 1개
- 다음 자동 조치 1개

행동 버튼:
- `전략상태 보기`

#### F. 빠른 진입
버튼 4개 고정
- 수익 보기
- 거래기록 보기
- 전략상태 보기
- 입출금 보기

### 데이터 소스
- 계좌 요약 API
- 최근 signals
- 최근 fills/trades
- 전략상태 요약 view model

### 빈 상태 처리
- 최근 신호 없음: `아직 최근 신호가 없습니다`
- 최근 체결 없음: `최근 체결이 없습니다`
- 전략 상태 없음: `전략 상태 데이터를 불러오는 중입니다`

### 홈에서 절대 전면 배치하지 않을 것
- raw artifact row
- 정합성 상세 사례 목록 전체
- operator/debug 코드
- bundle, provenance, internal phase row

## 2. 거래기록 상세 명세

### 페이지 목적
사용자가 `신호 -> 드롭 -> 주문 -> 포지션 -> 체결` 흐름을 거래소 화면처럼 읽게 한다.

### 화면 구조

#### A. KPI 줄
고정 카드 5개
1. 최근 신호 수
2. 최근 드롭 수
3. 대기 주문 수
4. 현재 포지션 수
5. 최근 체결 수

#### B. 메인 2열 표

##### 왼쪽: `최근 신호`
컬럼:
- 시각
- 마켓
- 방향
- 등급
- 상태
- 후속 결과

후속 결과 예:
- 체결됨
- 대기 주문
- 드롭됨
- 후속 없음

##### 오른쪽: `최근 드롭`
컬럼:
- 시각
- 마켓
- 방향
- 드롭 사유
- 차단 정책

차단 정책 예:
- EV 정책
- 쿨다운
- 전략 게이트
- 기타

#### C. 보조 2열 패널

##### 왼쪽: `현재 포지션`
컬럼:
- 마켓
- 방향
- 크기
- 평균가
- 미실현 손익

##### 오른쪽: `대기 주문`
컬럼:
- 마켓
- 방향
- 주문가
- 상태
- 만료/취소 여부

#### D. 하단 전체 폭: `최근 체결`
컬럼:
- 시각
- 마켓
- 방향
- 체결가
- 수량
- 손익

#### E. 하단 보조: `드롭 사유 요약`
카드 또는 배지로 노출
- EV 정책
- 쿨다운
- 전략 게이트
- 기타

### 데이터 소스
- signals
- signals_dropped
- order_intents
- positions
- fills/trades

### 빈 상태 처리
- 최근 신호 없음: `최근 신호가 없습니다`
- 최근 드롭 없음: `최근 드롭이 없습니다`
- 포지션 없음: `현재 열린 포지션이 없습니다`
- 대기 주문 없음: `현재 대기 주문이 없습니다`
- 최근 체결 없음: `최근 체결이 없습니다`

### 거래기록에서 강조할 것
- `드롭 사유`를 신호와 동급으로 다룬다.
- 신호가 많아도 체결이 없으면 그 사실이 드러나야 한다.
- 포지션/대기 주문은 항상 상단 절반 안에 보여야 한다.

### 거래기록에서 숨길 것
- audit용 raw log
- provenance/debug 코드
- 세부 stage row
- 과도한 운영 설명

## 3. 전략상태 상세 명세

### 페이지 목적
사용자가 전략 시스템의 현재 상태와 서버 우선 전환 진행 상황을 이해하게 한다.

### 화면 구조

#### A. 상단 KPI 줄
고정 카드 5개
1. 서버 우선 전환 진행률
2. 현재 단계
3. 현재 신호 원천
4. 실행 TF
5. 활성 마켓 수

#### B. 중단 2열 패널

##### 왼쪽: `정본 신호 상태`
항목:
- 24시간 정본 신호 수
- 최근 정본 신호 시각
- 정본 실행 품질 상태
- intent 전환율
- fill 전환율

##### 오른쪽: `Pine 비교 상태`
항목:
- 24시간 Pine 그림자 수
- 정합성 차이 상태
- 최근 mismatch 수
- 주요 드리프트 가족

#### C. 하단 2열 패널

##### 왼쪽: `최근 드리프트 사례`
목록 3~5건
항목:
- 마켓
- 등급
- 주된 이유
- 관측 시각

##### 오른쪽: `현재 막는 이유`
항목:
- 현재 우선 blocker
- EV 정책 차이
- 쿨다운 차이
- 전략 게이트 차이

#### D. 마지막 2열 패널

##### 왼쪽: `자연 진화 상태`
항목:
- 현재 목표 회복 상태
- 오토파일럿 상태
- 권한/승격 상태

##### 오른쪽: `다음 자동 조치`
항목:
- 조치 1
- 조치 2
- 사용자가 봐야 할 체크포인트

### 데이터 소스
- server_signal_authority_latest
- server_signal_quality_latest
- server_signal_runtime_latest
- server_signal_cutover_readiness_latest
- autonomy contract latest
- loop monitor latest

### 빈 상태 처리
- 데이터 없음: `전략 상태를 계산 중입니다`
- 드리프트 사례 없음: `최근 드리프트 사례가 없습니다`
- 자동 조치 없음: `현재 예약된 자동 조치가 없습니다`

### 전략상태에서 강조할 것
- `지금 정상인가`
- `왜 아직 100% 전환이 아닌가`
- `다음으로 시스템이 무엇을 할 것인가`

### 전략상태에서 숨길 것
- raw rows 전체
- provenance/debug 문자열
- bundle/operator/debug dump
- 세부 내부 코드 수치 전체

## 4. 공통 컴포넌트 명세

### 상태 배지
종류:
- 정상
- 주의
- 위험
- 진행 중
- 비교 중

원칙:
- 코드명이 아니라 해석된 말로 표시
- 색만으로 의미를 전달하지 않고 텍스트를 같이 둔다

### 표 스타일
원칙:
- 헤더는 짧고 고정
- 행 높이는 촘촘하지만 읽히게
- 숫자는 우측 정렬
- 시간/가격/수량은 모노

### CTA 버튼
기본 버튼:
- 수익 보기
- 거래기록 보기
- 전략상태 보기
- 입출금 보기

원칙:
- 홈에서 과도한 제어 버튼 금지
- 이동 버튼 중심

## 5. 구현 전 확정해야 할 사항
1. `수익` 페이지의 정보 구조를 전체 기준으로 삼는 것에 최종 동의
2. 새 사이트의 기본 메뉴를
- 홈
- 수익
- 입출금
- 거래기록
- 전략상태
- 설정
으로 고정
3. legacy 접근 방식을
- 별도 경로
또는
- `?legacy=1`
중 하나로 확정
4. 실제 구현 우선순위를
- 홈
- 거래기록
- 전략상태
순으로 고정
