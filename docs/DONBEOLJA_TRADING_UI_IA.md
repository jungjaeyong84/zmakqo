# DONBEOLJA Trading UI IA

## 목적
이 문서는 돈벌자를 `바이낸스 스타일 자동 코인 선물 거래 제품`으로 다시 설계하기 위한 사용자 중심 IA와 UX 원칙을 정리한다.

전제는 아래와 같다.
- 서버가 정본 신호를 생성하고 실행한다.
- Pine는 차트 시각화와 비교용 shadow로 유지한다.
- 사용자는 사이트에서 자산, 수익, 신호, 드롭, 전략 상태, 설정을 읽어야 한다.
- 현재 `수익` 페이지의 정보 구조를 전체 사이트의 기준으로 삼는다.
- 기존 사이트는 legacy 백업으로 유지한다.

## 최상위 메뉴 구조
새 사이트의 상단 메뉴는 아래처럼 고정한다.
1. 홈
2. 수익
3. 입출금
4. 거래기록
5. 전략상태
6. 설정

이 구조는 사용자의 질문 순서를 반영한다.
- 지금 돈이 어떤가
- 얼마나 벌고 있나
- 거래는 어떻게 되고 있나
- 전략은 정상인가
- 설정은 어떻게 되어 있나

## 페이지별 목적

### 1. 홈
목적:
- 사용자가 5초 안에 현재 자산과 거래 상태를 파악하게 한다.

핵심 질문:
- 지금 총자산이 얼마인가
- 오늘 손익이 어떤가
- 최근 신호와 체결이 있었나
- 전략이 정상인가

구성:
- 총자산
- 가용 자금
- 사용 중 자금
- 오늘/7일/30일 손익
- 최근 신호 요약
- 최근 체결 요약
- 전략 상태 요약
- 빠른 진입 버튼

### 2. 수익
목적:
- 기간별 성과와 누적 성과를 가장 쉽게 분석하게 한다.

핵심 질문:
- 얼마나 벌고 있나
- 어느 기간에서 좋아졌나 나빠졌나
- 어떤 마켓이 성과에 기여했나

구성:
- 기간 전환
- KPI 카드
- 누적 차트
- 일별 분포
- 마켓별 기여도
- 레버리지/성과 보조 요약

### 3. 입출금
목적:
- 자금 흐름을 별도 카테고리로 관리한다.

핵심 질문:
- 돈이 언제 들어오고 나갔나
- 최근 자금 변화가 수익과 어떤 관계가 있나

구성:
- 입금/출금/이체 내역
- 최근 자금 변화 요약
- 자금 관련 보조 메모

### 4. 거래기록
목적:
- 신호, 드롭, 주문, 포지션, 체결을 거래소형 화면으로 읽게 한다.

핵심 질문:
- 최근 신호가 나왔나
- 왜 드롭됐나
- 주문/체결은 됐나
- 현재 포지션은 무엇인가

구성:
- 상단 KPI
  - 최근 신호 수
  - 최근 드롭 수
  - 대기 주문 수
  - 현재 포지션 수
  - 최근 체결 수
- 메인 표
  - 최근 신호
  - 최근 드롭
  - 최근 체결
- 보조 패널
  - 현재 포지션
  - 대기 주문
  - 드롭 사유 분포

### 5. 전략상태
목적:
- 자연 진화와 서버 우선 전환 상태를 사용자도 읽을 수 있게 설명한다.

핵심 질문:
- 전략은 지금 정상인가
- 서버 우선 전환은 얼마나 진행됐나
- 왜 아직 100% 전환이 아닌가
- 다음 자동 조치는 무엇인가

구성:
- 서버 우선 전환 진행률
- 현재 단계
- 현재 신호 원천
- 실행 TF
- 활성 마켓 수
- 정본 신호 상태
- Pine 그림자 비교 상태
- 정본 실행 품질
- 최근 드리프트 사례
- 현재 막는 이유
- 다음 자동 조치

### 6. 설정
목적:
- 거래소, 리스크, 실행, AI 설정을 관리한다.

핵심 질문:
- 현재 운영 기준은 무엇인가
- 무엇을 바꾸면 위험해지는가

구성:
- 거래소 설정
- 리스크 설정
- 실행 모드
- AI/자동화 설정
- 저장과 변경 이력

## 디자인 방향

### 1. 시각 방향
- Binance 계열의 명확한 거래 제품 톤
- 밝은 뉴트럴/오프화이트 배경
- 골드 포인트 컬러
- 상승은 그린
- 하락과 위험은 레드

### 2. 정보 구조 방향
- Hero + KPI + 테이블 + 상태 카드
- 숫자는 크게
- 표는 거래소형으로 촘촘하게
- 상태는 badge와 짧은 문장으로

### 3. 타이포 방향
- 숫자, 가격, 시간은 모노 강화
- 제목은 짧고 강하게
- 설명은 한 줄 중심

### 4. 모바일 방향
- 모바일에서는 카드 우선 단일열
- 테이블은 중요 열만 남기고 축소

## 왜 현재 수익 페이지를 기준 스타일로 삼는가
현재 [profit.ejs](/Users/jeongjaeyong/Projects/donbeolja/src/views/profit.ejs)는 아래 강점이 있다.
- 상단 목적이 분명하다.
- 핵심 숫자가 먼저 나온다.
- 기간 전환이 직관적이다.
- 카드, 표, 차트가 역할별로 분리되어 있다.
- 정보 밀도가 높아도 읽기 어렵지 않다.

따라서 새 사이트는 `수익` 페이지의 정보 구조를 기준으로 삼고, 여기에 Binance 계열 시각 톤을 결합하는 방식이 맞다.

## 왜 기존 사이트를 백업으로 남겨야 하는가
기존 사이트는 바로 지우면 안 된다.

이유:
1. 현재 운영 데이터와 연결된 화면이 많다.
2. 자연 진화와 서버 전환 과정에서 비교가 필요하다.
3. 일부 내부 운영 정보는 여전히 legacy 화면에서 확인해야 할 수 있다.
4. 새 UI는 사용자 중심이고, legacy는 운영/감사 백업으로 가치가 있다.

백업 원칙:
- 기존 `home/state/control-plane`는 그대로 남긴다.
- 새 화면이 기본 진입점이 된다.
- 기존 화면은 `legacy` 경로 또는 `?legacy=1`로 접근한다.

## 최종 UX 기준
새 돈벌자 사이트는 아래 기준을 만족해야 한다.
1. 홈에서 돈과 결과가 먼저 보여야 한다.
2. 수익 페이지는 전체 사이트의 기준 톤이 되어야 한다.
3. 거래기록은 신호·드롭·체결이 명확히 읽혀야 한다.
4. 전략상태는 운영자만 이해하는 화면이 아니라 사용자도 현재 상태를 이해할 수 있어야 한다.
5. Pine는 실행 정본이 아니라 비교와 시각화 용도임이 명확해야 한다.
6. 기존 사이트는 사라지는 것이 아니라 백업 경로로 남아 있어야 한다.
