# Kiwoom REST 연동 고려사항 (요약)

## 1) 운영 원칙(돈벌자 Ω 규율 유지)
- **확정봉 기준**: 신호/집행/로그/리포트는 확정봉 기준으로만 처리.
- **Signal → Intent → Fill → Position** 파이프라인 유지.
- **Gate/Idempotency/Replay** 규칙을 동일 적용.
- **Phase0에서도 LIVE 허용**(단, 실행 모드는 시스템 설정으로 제어).

## 2) 인증/키 관리
- REST 토큰: `POST /oauth2/token` (client_credentials)
- **APP KEY/SECRET은 서버에서만 보관** (프론트 노출 금지).
- **모의/실서버 분리**: mock(모의)은 KRX 한정.

## 3) 거래시간/장 캘린더
- KRX는 24/7이 아님 → **세션 기반 Gate** 필요.
- 휴장/조기폐장/VI/서킷브레이커 등은 **신규 진입 차단** 우선.

## 4) 주문 스펙(현물 롱 중심)
- 주문 엔드포인트: `POST /api/dostk/ordr`
- TR 코드: kt10000(매수), kt10001(매도), kt10002(정정), kt10003(취소)
- 필드 핵심: `dmst_stex_tp`, `stk_cd`, `ord_qty`, `ord_uv`, `trde_tp`

## 5) 최소 주문/호가 단위(기본표)
- **호가 단위(예시)**
  - < 1,000: 1원
  - < 5,000: 5원
  - < 10,000: 10원
  - < 50,000: 50원
  - < 100,000: 100원
  - < 500,000: 500원
  - ≥ 500,000: 1,000원
- **최소 주문**: 1주 + 최소 주문금액(예: 1,000원 이상)

## 6) 계좌/잔고/체결
- 계좌 요약 TR: `ka01690` (예수금/보유종목)
- 체결/미체결 조회는 추가 TR 연동 필요(확장 단계).

## 7) 데이터/봉 조회
- 분봉/일봉/주봉/월봉 TR 사용
- TF 매핑은 엔진 기준과 통합(예: 60m 신호 / 15m 실행 TF)

## 8) 확장 로드맵(권장)
1. REST 기반 계좌/주문 기본 구현
2. WS 기반 체결/잔고 동기화
3. 레짐/세션 기반 Gate 강화

## 9) 위험/안전장치
- API 실패 연속 시 **자동 중지**
- VI/갭 리스크는 **진입 보류**
- 비용(수수료/슬리피지/세금)은 **입력값만 적용**
