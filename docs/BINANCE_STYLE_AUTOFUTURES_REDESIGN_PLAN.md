# Binance-Style Auto Futures Redesign Plan

## 목적
돈벌자 사이트를 `자동화 코인 선물 거래 제품`처럼 다시 설계한다.

핵심 목표는 아래 5가지를 사용자가 한눈에 읽게 만드는 것이다.
1. 신호 생성
2. 신호 드롭
3. 자연 진화 상태
4. 수익
5. 설정

기존 사이트는 바로 지우지 않는다.
- 기존 화면은 `백업 화면`으로 남긴다.
- 새 기본 화면은 사용자 중심 제품 화면으로 바꾼다.

## 핵심 원칙
- 서버 정본, Pine 그림자 구조는 유지한다.
- 사이트는 `운영자 콘솔`보다 `거래 제품`처럼 보여야 한다.
- 화면 문구는 기술 구현보다 사용자 행동 기준으로 쓴다.
- 수익 화면은 현재 디자인을 기준 스타일로 삼는다.
- 첫 화면에서 복잡한 내부 용어를 최대한 숨기고, 필요한 곳에서만 드러낸다.

## 새 정보 구조
### 1. 홈
목표:
- 현재 자산
- 오늘/주간/월간 수익
- 최근 신호/체결
- 전략 상태
를 가장 먼저 보여준다.

보여줄 것:
- 총자산
- 가용 자금
- 사용 중 자금
- 총 손익
- 오늘/7일/30일/6개월 손익
- 최근 신호 5~10건
- 최근 체결 5~10건
- 전략 상태 요약

숨길 것:
- 개발자용 긴 설명
- 과도한 제어 버튼
- 내부 시스템 세부 row

### 2. 수익
목표:
- 현재 `수익` 페이지를 메인 수익 분석 화면으로 유지한다.

원칙:
- 현재 카드/차트/요약 구조를 유지
- 새 공용 쉘 톤에 맞게만 조정
- 사용자가 가장 익숙한 화면으로 취급

### 3. 입출금
목표:
- 자금 흐름을 별도 카테고리로 유지한다.

### 4. 거래기록
목표:
- 신호, 드롭, 체결, 포지션, 대기 주문을 거래소처럼 본다.

섹션:
- 실행 요약 상단 카드
- 현재 포지션/주문 상태 표
- 신호 드롭 요약 카드
- 최근 신호 표
- 최근 체결 표

우선순위:
- 사용자가 지금 거래가 어떤 상태인지 바로 읽어야 한다.
- `신호 없음`, `드롭 증가`, `체결 없음` 같은 상태를 직관적으로 보여줘야 한다.

### 5. 전략상태
목표:
- 자연 진화와 서버 우선 전환을 사람이 읽을 수 있게 보여준다.

핵심 질문:
- 지금 전략이 정상인가?
- 서버 정본 전환은 얼마나 됐나?
- 왜 아직 완전히 전환되지 않았나?
- 다음 자동 조치는 무엇인가?

섹션:
- 전환 진행률
- 정본/그림자 드리프트
- 정본 실행 품질
- 최근 mismatch/drift 사례
- 자연 진화/오토파일럿 요약

### 6. 설정
목표:
- 거래소, 리스크, 실행, AI 설정을 별도 화면에서 관리한다.

## 디자인 방향
### 톤
- Binance 스타일의 어두운 거래 화면
- 숫자는 크게
- 상태는 짧게
- 핵심 액션은 명확히

### 컬러
- 배경: 밝은 뉴트럴/오프화이트
- 강조: 바이낸스 계열 골드
- 상승: 그린
- 하락/위험: 레드
- 보조 정보: 쿨 그레이/슬레이트

### 타이포
- 제목은 강하게
- 본문은 짧고 읽기 쉽게
- 숫자와 시간은 모노스페이스 비중 확대

### 레이아웃 원칙
- Hero + KPI + 표/패널 구조
- 데스크톱에서는 거래소 느낌의 다단 배치
- 모바일에서는 카드 중심 단일열 축소

## 사용자 언어 원칙
사용자에게 먼저 보여줄 말:
- 현재 총자산
- 가용 자금
- 오늘 손익
- 최근 신호
- 최근 체결
- 전략 상태
- 드롭 사유
- 전환 진행률

가급적 줄일 말:
- Mission Control
- Control Surface
- Provenance
- Execution SOT
- Bundle Deployment
- Operator Strip

필요하면 아래처럼 번역해서 쓴다.
- Source Mode -> 신호 원천
- Parity Drift -> 정합성 차이
- Server Primary -> 서버 우선 전환
- Shadow Pine -> Pine 그림자

## 백업 유지 전략
기존 화면은 즉시 삭제하지 않는다.

원칙:
- 기존 `home/state/control-plane`는 백업으로 남긴다.
- 새 메인 화면은 동일 라우트에서 기본 렌더된다.
- 기존 화면은 `legacy` 경로 또는 `?legacy=1`로 접근한다.

## 구현 순서
1. 설계 문서 고정
2. 백업 접근 경로 추가
3. 새 공용 쉘 추가
4. 새 홈 구현
5. 새 거래기록 구현
6. 새 전략상태 구현
7. 수익/입출금 공용 쉘 톤 통일
8. 검증

## Claude 검토 포인트
Claude에게 보여줄 때 확인할 것:
1. 홈에서 무엇을 제일 먼저 봐야 하는지 순서가 맞는가
2. 거래기록이 실제 거래소처럼 읽히는가
3. 전략상태가 너무 운영자/개발자 화면처럼 보이지 않는가
4. 현재 수익 페이지를 기준 디자인으로 삼는 방향이 맞는가
5. 전체 톤이 자동 코인 선물 거래 제품처럼 느껴지는가
