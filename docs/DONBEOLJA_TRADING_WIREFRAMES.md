# DONBEOLJA Trading Wireframes

## 목적
이 문서는 새 돈벌자 사이트의 `홈`, `거래기록`, `전략상태` 화면을 실제 구현 전에 와이어 수준으로 고정하기 위한 계획 문서다.

전제는 아래와 같다.
- 돈벌자는 바이낸스 스타일의 정보 구조를 갖춘 자동 코인 선물 거래 제품으로 재설계한다.
- `수익` 페이지의 정보 구조와 읽기 쉬움을 기준 스타일로 삼는다.
- `서버 = 정본`, `Pine = 시각화/비교 shadow` 구조는 유지한다.
- 기존 사이트는 `legacy`로 남기고, 새 화면을 기본 진입점으로 설계한다.

---

## 공통 레이아웃 원칙

### 1. 상단 구조
모든 주요 화면은 아래 공통 구조를 가진다.
1. 페이지 제목
2. 짧은 설명 한 줄
3. 핵심 KPI 카드 3~6개
4. 메인 표 또는 상태 패널
5. 보조 패널

### 2. 정보 우선순위
- 숫자와 현재 상태를 가장 먼저 보여준다.
- 설명은 한 줄만 쓴다.
- 사용자가 지금 해야 할 판단이 무엇인지 바로 보이게 한다.
- 원시 artifact row, 내부 코드, 긴 진단 문자열은 기본 화면에서 숨긴다.

### 3. 시각 원칙
- 밝은 뉴트럴 배경
- 골드 포인트
- 상승 그린 / 하락 레드
- 모노스페이스 숫자/시간/가격
- 표는 거래소형으로 촘촘하게

### 4. 공통 인터랙션 원칙
- 상세 정보는 `상세 보기` 또는 `펼치기`로 뒤로 뺀다.
- 최근 5~10건만 기본 노출한다.
- 추가 목록은 별도 전체 보기 링크로 넘긴다.
- 모바일에서는 KPI -> 핵심 표 -> 보조 패널 순으로 한 줄 배치한다.

## 홈 와이어

### 페이지 질문
- 지금 총자산이 얼마인가
- 오늘 손익이 어떤가
- 최근 신호와 체결이 있었나
- 전략이 정상인가

### 목표
사용자가 첫 화면에서 `돈`, `결과`, `최근 움직임`, `전략 상태`를 5초 안에 파악하게 한다.

### 데스크톱 와이어

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 홈                                                                  │
│ 자동 코인 선물 거래의 현재 자산, 수익, 신호, 전략 상태를 한눈에 보기 │
├──────────────────────────────────────────────────────────────────────┤
│ [총자산] [가용 자금] [오늘 손익] [최근 7일 손익] [최근 체결 수]       │
├───────────────────────────────┬──────────────────────────────────────┤
│ 자금과 손익                    │ 최근 신호 / 최근 체결                 │
│ - 총자산                       │ - 최근 신호 5건                       │
│ - 사용 중 자금                 │ - 최근 체결 5건                       │
│ - 오늘/7일/30일 손익           │ - 신호 등급 / 방향 / 시각             │
│ - 수익 보기 버튼               │ - 거래기록 보기 버튼                  │
├───────────────────────────────┼──────────────────────────────────────┤
│ 쉬운 수익 카테고리              │ 전략 상태 요약                        │
│ - 오늘                          │ - 서버 우선 전환 진행률               │
│ - 최근 7일                      │ - 현재 신호 원천                      │
│ - 최근 30일                     │ - 정본 신호 상태                      │
│ - 최근 6개월                    │ - 다음 자동 조치                      │
│ - 총 손익                       │ - 전략상태 보기 버튼                  │
├──────────────────────────────────────────────────────────────────────┤
│ 빠른 진입                                                            │
│ [수익 보기] [거래기록 보기] [전략상태 보기] [입출금 보기]            │
└──────────────────────────────────────────────────────────────────────┘
```

### 모바일 와이어

```text
[홈]
[총자산]
[가용 자금]
[오늘 손익]
[최근 7일 손익]

[최근 신호 5건]
[최근 체결 5건]

[쉬운 수익 카테고리]
- 오늘
- 7일
- 30일
- 6개월
- 총 손익

[전략 상태 요약]
- 전환 진행률
- 정본 신호 상태
- 다음 자동 조치

[빠른 진입 버튼 4개]
```

### 홈에서 반드시 보여줄 것
- 총자산
- 가용 자금
- 사용 중 자금
- 오늘/7일/30일 손익
- 최근 신호
- 최근 체결
- 전략 상태 요약

### 홈에서 숨길 것
- 긴 운영 설명
- raw artifact row
- 개발자용 상태 코드
- 상세 drift 사례 전체 목록
- 지나치게 많은 버튼

### 홈에서 쓰는 용어
유지:
- 총자산
- 가용 자금
- 최근 신호
- 최근 체결
- 전략 상태

피해야 할 것:
- Mission Control
- Control Surface
- Execution SOT

## 거래기록 와이어

### 페이지 질문
- 최근 신호가 나왔나
- 왜 드롭됐나
- 주문과 체결은 됐나
- 현재 포지션은 무엇인가

### 목표
사용자가 거래 흐름을 `신호 -> 드롭 -> 주문 -> 포지션 -> 체결` 순서로 읽게 한다.

### 데스크톱 와이어

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 거래기록                                                              │
│ 최근 신호, 드롭, 주문, 포지션, 체결 상태를 거래소형 화면으로 보기     │
├──────────────────────────────────────────────────────────────────────┤
│ [최근 신호 수] [최근 드롭 수] [대기 주문 수] [현재 포지션 수] [체결 수]│
├───────────────────────────────┬──────────────────────────────────────┤
│ 최근 신호                      │ 최근 드롭                            │
│ 표 컬럼:                       │ 표 컬럼:                             │
│ 시간 / 마켓 / 방향 / 등급      │ 시간 / 마켓 / 방향 / 드롭 사유       │
│ 상태 / 후속 결과               │ 차단 정책 / 영향                      │
├───────────────────────────────┼──────────────────────────────────────┤
│ 현재 포지션                     │ 대기 주문                             │
│ 표 컬럼:                        │ 표 컬럼:                              │
│ 마켓 / 방향 / 크기 / 평균가     │ 마켓 / 방향 / 가격 / 상태              │
│ 미실현 손익                     │ 만료 / 취소 상태                       │
├──────────────────────────────────────────────────────────────────────┤
│ 최근 체결                                                              │
│ 표 컬럼: 시간 / 마켓 / 방향 / 체결가 / 수량 / 손익                    │
├──────────────────────────────────────────────────────────────────────┤
│ 드롭 사유 요약                                                          │
│ [EV 정책] [쿨다운] [전략 게이트] [기타]                                │
└──────────────────────────────────────────────────────────────────────┘
```

### 모바일 와이어

```text
[거래기록]
[KPI 5개]

[최근 신호]
[최근 드롭]
[현재 포지션]
[대기 주문]
[최근 체결]
[드롭 사유 요약]
```

### 거래기록에서 반드시 보여줄 것
- 최근 신호 수
- 최근 드롭 수
- 현재 포지션 수
- 대기 주문 수
- 최근 체결 수
- 최근 신호 표
- 최근 드롭 표
- 최근 체결 표
- 드롭 사유 요약

### 거래기록에서 숨길 것
- 실행 감사용 긴 로그
- provenance/raw code
- 운영자용 세부 이벤트 체인
- 너무 많은 상태 배지 남발

### 거래기록에서 중요한 UX 원칙
1. `드롭`은 신호와 동급으로 보여야 한다.
2. 최근 체결이 없으면 그 상태를 빈 화면이 아니라 메시지로 보여야 한다.
3. 현재 포지션과 대기 주문은 항상 눈에 띄는 별도 패널이어야 한다.
4. `신호 없음`, `드롭 증가`, `체결 없음`은 경고형 상태로 보이게 한다.

## 전략상태 와이어

### 페이지 질문
- 전략은 지금 정상인가
- 서버 우선 전환은 얼마나 진행됐나
- 왜 아직 100%가 아닌가
- 다음 자동 조치는 무엇인가

### 목표
자연 진화와 서버 전환 상태를 운영자만이 아니라 일반 사용자도 읽을 수 있게 만든다.

### 데스크톱 와이어

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 전략상태                                                              │
│ 자동 전략의 현재 상태와 서버 우선 전환 진행 상황을 읽기 쉽게 보기     │
├──────────────────────────────────────────────────────────────────────┤
│ [전환 진행률] [현재 단계] [신호 원천] [실행 TF] [활성 마켓 수]         │
├───────────────────────────────┬──────────────────────────────────────┤
│ 정본 신호 상태                  │ Pine 비교 상태                        │
│ - 24h 정본 신호 수             │ - 24h Pine 그림자 수                 │
│ - 최근 정본 신호 시각          │ - 최근 비교 상태                     │
│ - 정본 실행 품질 상태          │ - 최근 mismatch 수                   │
├───────────────────────────────┼──────────────────────────────────────┤
│ 최근 드리프트 사례              │ 현재 막는 이유                        │
│ - 마켓                         │ - EV 정책 차이                       │
│ - 등급                         │ - 쿨다운 차이                        │
│ - 주된 이유                    │ - 전략 게이트 차이                   │
│ - 관측 시각                    │ - 현재 우선 blocker                  │
├───────────────────────────────┼──────────────────────────────────────┤
│ 자연 진화 상태                  │ 다음 자동 조치                        │
│ - 현재 목표 회복 상태          │ - 다음 자동 조치 1                   │
│ - 오토파일럿 상태              │ - 다음 자동 조치 2                   │
│ - 현재 권한/승격 상태          │ - 사용자가 봐야 할 체크 포인트       │
└──────────────────────────────────────────────────────────────────────┘
```

### 모바일 와이어

```text
[전략상태]
[전환 진행률]
[현재 단계]
[신호 원천]
[실행 TF]
[활성 마켓 수]

[정본 신호 상태]
[Pine 비교 상태]
[최근 드리프트 사례]
[현재 막는 이유]
[자연 진화 상태]
[다음 자동 조치]
```

### 전략상태에서 반드시 보여줄 것
- 서버 우선 전환 진행률
- 현재 단계
- 신호 원천
- 실행 TF
- 활성 마켓 수
- 정본 신호 상태
- Pine 비교 상태
- 최근 드리프트 사례
- 현재 막는 이유
- 다음 자동 조치

### 전략상태에서 숨길 것
- raw artifact 전체 row
- provenance/debug 문자열
- bundle/operator/debug dump
- 내부용 세부 수치 전체
- stage row 원본 전체 목록

### 전략상태 UX 원칙
1. 사용자는 `지금 정상인가`를 먼저 읽어야 한다.
2. 그 다음 `왜 아직 완전히 전환되지 않았나`가 보여야 한다.
3. 마지막으로 `다음 자동 조치`를 읽어야 한다.
4. drift와 blocker는 코드명이 아니라 해석된 한국어로 보여야 한다.

## 페이지 간 연결 플로우

### 기본 사용자 흐름
1. `홈`
- 현재 자산과 손익 확인
2. `수익`
- 기간별 성과 확인
3. `거래기록`
- 최근 신호, 드롭, 체결 확인
4. `전략상태`
- 전략과 서버 전환 상태 확인
5. `설정`
- 필요 시 운영 기준 조정

### 전략 점검 흐름
1. 홈에서 전략 상태 요약 배지 확인
2. 이상이 있으면 `전략상태` 이동
3. blocker 확인
4. 필요 시 `거래기록`에서 최근 드롭/체결 흐름 확인

### 성과 점검 흐름
1. 홈에서 오늘 손익 확인
2. `수익` 이동
3. 기간별 성과와 마켓 기여 확인
4. 필요 시 `거래기록`에서 최근 신호와 체결 확인

## legacy 백업 전략
와이어 기준에서도 백업 전략은 고정한다.
1. 기존 `home/state/control-plane`는 유지
2. 새 화면이 기본 진입점
3. 기존 화면은 `legacy` 경로 또는 `?legacy=1`
4. 새 와이어 적용 우선순위는 아래와 같다.
- 홈
- 거래기록
- 전략상태
- 그 다음 수익/입출금 공용 쉘 통일

## 다음 구현 전 체크리스트
1. 이 와이어 구조가 사용자 질문 순서와 맞는지 확인
2. `수익` 페이지의 정보 구조를 전체 기준으로 삼는 데 동의 여부 확인
3. `홈 / 거래기록 / 전략상태` 세 화면만 먼저 새로 만드는 순서에 동의 여부 확인
4. legacy 접근 방식을 `별도 경로`로 할지 `?legacy=1`로 할지 확정
5. 그 다음에만 실제 UI 구현 시작
